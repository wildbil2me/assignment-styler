How to run it

Repeat for each surface you care about: bulletin board, topic, assignment. Twenty minutes total.

  1. Copy the probeUse the button below. It copies only the probe payload, not this page.
  2. Paste into Blackbaud's HTML/source editorNot the visual editor. Save the draft.
  3. Look at it against the reference rendering belowEvery row states what you should see. Note anything that differs.
  4. Now the important one: open the visual editor, then save againThis is where editors classically mangle markup, and it is the likeliest way a teacher silently loses their formatting.
  5. Reopen the source editor and copy everything outThat text is what Blackbaud actually stored.

Reference rendering

What the probe looks like when nothing has been stripped. Compare this against what you see in Blackbaud — the differences are the findings.

What each row is for

Stakes are relative to the chosen soft-cards direction and the zero-backend architecture, not to CSS in general.

Tier 1 — Decides the chosen direction and the architecture 8 rows

R01critical
inline style on a div
The baseline assumption of the entire design. If this fails, nothing else matters and the project needs a different strategy.
R02critical
border-radius
Soft cards is built on this. If it is stripped, the chosen direction degrades to flat squares and the pick is worth revisiting.
R03critical
box-shadow
The other half of soft cards. Provides the layering that reads as modern.
R04critical
tinted background-color
Every non-hero block is a tinted surface. Also the safest fallback if radius and shadow are stripped.
R05high
rgba() colour values
Shadows and subtle overlays depend on alpha. If rgba is rewritten to hex, transparency is lost silently.
R06critical
<style> block with a class rule
THE architectural question. If a style block survives, the whole inline-only strategy is optional and motion becomes possible.
R07critical
inline-block + calc() + min-width
The current half-width strategy, and the one piece of real cleverness in the renderer: responsive stacking with no media query. Verify before anything is built on it.
R08high
thick border-left accent bar
Core to the visual identity across all three directions, and the cheapest way to signal block type if fills are stripped.

Tier 2 — Layout alternatives and style delivery 9 rows

R09medium
display:flex
Would simplify layout enormously if it survives. Would let the half-width strategy stop being a trick.
R42high
flex-wrap on a flex row
Added 2026-08-12 by Phase 2. The renderer's half-width row asks for display:flex so two cards reach equal heights, but flex without wrapping overflows a phone instead of stacking — so the wrapper is only emitted when this row passes. R09 established that display:flex survives and that unknown properties in the same attribute (gap) come back intact, which is why core/compat.ts currently infers this as true. This row settles it.
R10medium
display:grid
Same as flex. Also the only clean way to do a real multi-column study guide.
R11high
two-column <table>
The conservative fallback if every modern layout method fails. Email HTML has survived on tables for 25 years.
R12low
float:left
The older conservative fallback. Worth one row in case inline-block is the thing that fails.
R13high
max-width + margin:0 auto wrapper
The renderer's outer container. If the wrapper is stripped, every post runs the full width of the surface.
R14medium
class attribute retention
If classes survive but style blocks do not, a tenant-side stylesheet becomes an option worth knowing about.
R15medium
data-* attribute retention
The current renderer emits data-layout on every block. If data attributes are stripped, the importer loses its best round-trip signal.
R16medium
!important in an inline style
The escape hatch if Blackbaud injects competing CSS that beats our inline styles.

Tier 3 — Typography and modern feel 7 rows

R17medium
letter-spacing
Every eyebrow label in all three directions uses it. Its loss is cosmetic but pervasive.
R18low
opacity
Not used today. Would open up layering effects if available.
R19low
linear-gradient background
Not used today. A cheap way to add depth if shadows are stripped but gradients are not.
R20high
websafe font-family
Every preset pairs a websafe heading and body face. If font-family is stripped, all typographic identity goes with it.
R21low
non-websafe font-family
Confirms whether the websafe-only constraint is real or inherited superstition. It will not render without the font installed, but the declaration surviving is the finding.
R22critical
font-size and line-height
The type scale is most of what makes output feel considered rather than pasted.
R23low
text-transform: uppercase
Used for eyebrow labels. Cheap to work around by typing caps, but worth knowing.

Tier 4 — Elements and structure 21 rows

R24high
<h1> with inline style
Decides whether heading-order validation is meaningful, or whether headings get remapped to styled paragraphs.
R25medium
<h2> / <h3> / <h4>
Same question, for the subordinate levels the composer uses for block headings. The verdict is asserted on the h2; h3 and h4 render alongside so you can see whether the whole scale survives together.
R26medium
<blockquote>
The quote block. Also a good canary for whether semantic elements survive at all.
R27medium
<ul> with list-style-type:none
The checklist block renders a literal box character and suppresses the bullet. If none is stripped you get a bullet AND a box.
R28medium
<ol> numbering
The steps block.
R29medium
consecutive <br> runs
The rich-text editor emits these constantly. Editors often collapse or multiply them.
R30high
<a href> to https
The resource block. A link that loses its href is worse than no link.
R31medium
link target and rel hardening
Whether our link hardening survives, or whether Blackbaud rewrites it to its own policy.
R32high
<span style="color">
The sanitizer's allowlist narrows surviving styles to colour and background-colour on spans. If spans are unwrapped, that work is pointless.
R44high
<b> bold text
The composer’s Bold control emits this element. If Blackbaud unwraps it, the words survive but the teacher’s emphasis disappears.
R45high
<i> italic text
The composer’s Italic control emits this element. The existing blockquote test proves font-style survives, not that inline italic markup does.
R46high
<u> underlined text
The composer’s Underline control emits this element, and no earlier row tested it.
R47high
<strike> struck text
The composer’s Strikethrough control emits this legacy element in Chromium. If Blackbaud normalizes it to s, the analyzer should report rewritten so the sanitizer contract can follow the stored form.
R48high
text-align values
The composer now exposes left, center, right, and justified block alignment. Earlier evidence suggests every inline property survives, but these values have not been isolated.
R49high
combined rich inline formatting
Isolated tags can pass while the visual editor still flattens a realistic nested selection. This mirrors a teacher combining emphasis, colour, highlight, and a link in one block body.
R50high
list nested inside a rendered card
R27 and R28 test lists alone. The renderer places rich lists inside a body div, inside a card div, below an h2; this production-shaped row checks that Blackbaud does not flatten that nesting.
R33medium
emoji inside a heading
The block-icon feature, and soft cards uses emoji as its section markers.
R34medium
entities and &nbsp;
Whether esc() output is stable, or gets double-escaped into visible markup on round trip.
R35high
divs nested three deep
Wrapper, then block, then inner content. Exactly the renderer's structure.
R36low
<img> with inline width
Not used today. Decides whether images are ever viable in generated content.
R37low
inline <svg>
Would allow real icons instead of emoji, and is the only non-CSS animation channel that is not an image file.

Tier 5 — Motion (backburner, cheap to answer now) 5 rows

R38medium
@keyframes in a <style> block
The only route to real CSS animation. @keyframes cannot be expressed in an inline style attribute, so this row and R06 decide the whole motion question together.
R39low
SVG SMIL <animate>
Markup rather than CSS, so it needs no style block. The one motion channel that could work even if R06 and R38 both fail. Note it cannot honour prefers-reduced-motion.
R40medium
<details> / <summary>
Native progressive disclosure with zero CSS and no accessibility cost. The genuinely useful one for long study guides.
R43medium
<h2> inside <summary>
Added 2026-08-12 by Phase 4. Card headings became <h2> so the document has structure below its title, but a collapsible section's heading is its <summary>, and the renderer will not nest one inside the other until this row says the tenant keeps it. The HTML spec allows exactly one heading element as summary's content; whether Blackbaud's sanitizer knows that is the open question. Until it passes, collapsible sections contribute no heading and the compatibility panel says so.
R41low
animated GIF
Always works if images survive at all, and needs no CSS. Not embedded here to keep the probe small.
